## Scope

The request, the sample form, Gracie's answers, the scout's Technical Approach, the recommended design, the gotchas and the research sources all live in the parent story, [BF-58](BF-58-working-in-waterways-form.md). They are not repeated here. This story builds items 1 to 5 of the parent's Recommended design:

1. Migration: `projects.waterway_sites jsonb`, both form-type CHECK constraints extended with `working_in_waterways`, requirement rows backfilled for every project with a `waterway` permit, plus the rollback pair, rehearsed rolled back.
2. Sites editor (`WaterwaySitesField.tsx`) in project setup, shown when the Waterway NDEP permit is ticked.
3. Constants and wiring in the hand-wired places the scout listed (form type, labels, permit map, route maps, `FormType`, `EDIT_SUPPORTED`, photo storage paths), and removal of the BF-41 placeholder.
4. Zod schema with four check items, site snapshot, `photos.min(1)`; the shared photo schema extracted on this second caller.
5. Server actions (submit, edit) and the `new`, view and edit pages under `forms/working-in-waterways/`.
6. The Pacific-date helper (`America/Los_Angeles`) used for the entry form's default date.

Out of scope, in BF-58.2: the PDF template, the inspector renderer, the "sites with a form today" indicator, Gracie's sign-off.

## Interim behaviour until BF-58.2 ships

Between the two merges, submissions exist that have no PDF template and no dedicated inspector renderer. As of master `9d49227`:

- The PDF route answers an unknown template with HTTP 400 "PDF template not available", and `FormActions` shows the Download PDF button for every type.
- The inspector `FormDetail` falls back to a generic key-value list, which would print the photo array as raw JSON.

Neither may reach a user as a broken surface. The plan at /story picks the approach (for example, hide the PDF button for this type and exclude or plainly render it in the inspector portal until BF-58.2).

## Acceptance criteria

- [ ] A project with the Waterway NDEP permit lists the Working in Waterways form with no placeholder text, including the two existing production projects (NDOT 4541, RNO 18) through the backfill.
- [ ] Project admins can define the project's waterway sites in project setup: a name plus an optional descriptor. The Microsoft project can carry "Western Drainage" and "Eastern Drainage".
- [ ] A user can submit one form per site with every field from the sample except "Photo taken?", including a comment for each of the four check items. The server rejects a submission with no photo, and a site not on the project's list.
- [ ] The entry form's default date is today's date in Nevada, also after 5 pm PDT.
- [ ] View page and Edit (owner or admin) work; editing a record whose site was later renamed still saves.
- [ ] No broken interim surface: no PDF button that errors, no raw JSON in the inspector portal (see Interim behaviour).
- [ ] RLS: same organization-scoped visibility and BF-43 edit ownership as the other forms, verified with an ordinary user and an admin.
- [ ] Migration rehearsed rolled back before it is applied to production, with Tim's go.
- [ ] `pnpm build` and lint clean.
