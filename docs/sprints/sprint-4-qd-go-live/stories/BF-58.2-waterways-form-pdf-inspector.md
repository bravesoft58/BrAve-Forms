## Technical Approach

Scouted 2026-09-28T14:41:31Z. App code only: no migration, no new dependency.

**Build vs Use:** COPY the repo's own patterns. Already installed and used for the NDOT photo PDF: `@react-pdf/renderer` 4.3.2 and `browser-image-compression` 2.0.2. The PDF follows `ndot-stormwater.tsx` (its photo page) and `primitives.tsx`; the inspector renderer follows `NdotStormwaterDetail` inside `FormDetail.tsx` (its photo grid); the date comes from `pacificToday()` in `src/lib/dates.ts` (BF-58.1). No library replaces a per-form template. Reopen when the app needs a generic form-to-PDF renderer across more than these six types.

**Pieces and where they go:**

1. **Shared photo subfolder map** (parent design item; still hand-listed twice). New `src/lib/forms/photo-paths.ts` exporting `FORM_PHOTO_SUBPATH: Partial<Record<FormType, string>>` = `{ ndot_weekly_stormwater: "ndot-stormwater", working_in_waterways: "working-in-waterways" }`. Replaces `PHOTO_SUBPATH` in `src/app/api/forms/[submissionId]/pdf/route.ts` and `PHOTO_STORAGE_PATHS` in `src/lib/queries/inspector.ts`. Adding the Waterways entry is what makes both the PDF and the inspector sign its photos. The inspector path already caps each signed URL at the session's `accessUntil` (BF-56), so Waterways photos inherit that. `WaterwaysForm`'s `storagePath` literal `working-in-waterways` must stay equal to the map value.
2. **PDF** `src/lib/pdf/working-in-waterways.tsx` (about 120 lines): one LETTER page with the title banner and header fields (project, site and descriptor, date, time, initials), the four checks as label / answer / comment rows from `WATERWAY_CHECKS`, and the equipment block. Photos go below, or on a second page when there are several, as `<Image src={photo.url}>` with the caption or file name, copying NDOT page 3. Register it in `registry.ts`; `getPdfFilename` already maps the type. No permit number: `permitTypeMap` has no Waterway entry, and the parent design shows none.
3. **Inspector** `src/components/inspector/WorkingInWaterwaysDetail.tsx` replaces `WorkingInWaterwaysSummary.tsx` (delete it): the same fields plus a signed-photo grid copied from `NdotStormwaterDetail`. `FormDetail.tsx` changes only its import and one `case`. It is already 582 lines, a pre-existing breach of the 300-line rule, so it must not grow.
4. **Sites with a form today** `src/components/projects/WaterwaySitesToday.tsx` (about 50 lines), rendered in the Working in Waterways tab of `ProjectTabs.tsx`. Inputs: `project.waterway_sites` (already selected by `getProjectById`'s `*`) and today's Waterways submissions. `getProjectSubmissions` must also return the site: add `site_name:data->>site_name` to its select list (PostgREST's JSON path with an alias). For each site, show "Submitted today" or "No form today" where today is `pacificToday()` compared with `form_date`. Information only, with no warning styling. A submission whose site name is not in the current list (a renamed site) is listed as-is under its own name rather than dropped. The page renders per request, so "today" is computed at request time on the server.
5. **Remove the interim guards:** make `registry` a full `Record<FormType, PdfComponent>`, so TypeScript fails if any form type lacks a template; delete `PDF_SUPPORTED` and its check in `form-actions.tsx` (every type then has a template); delete both `TODO(BF-58.2)` comments.

**Photo rotation (parent gotcha, re-checked):**
- `@react-pdf/renderer` has applied JPEG EXIF orientation since PR #2529 (merged 2024-01-19, which fixes #1848). A related report, #2972 ("orientation of some images is incorrect"), is still open. [verified 2026-09-28]
- `browser-image-compression` returns the original file unchanged when it is already under `maxSizeMB` (1.5) and within `maxWidthOrHeight` (1920). So small photos reach Storage with their EXIF intact, and larger ones are redrawn upright on a canvas. [verified 2026-09-28]
- Residual risk is small photos that hit the #2972 case. The AC 5 phone-photo check stays, and should include one portrait photo taken on an iPhone and one on Android.
