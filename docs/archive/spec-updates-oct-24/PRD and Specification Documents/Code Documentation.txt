## 2. Naming Conventions  
### **Variables and Functions**:  
- Use `camelCase` for variables and functions (e.g., `userName`, `fetchLogs`).  
- Use descriptive names that reflect the purpose of the variable or function.  

### **Components**:  
- Use `PascalCase` for React components (e.g., `LogForm`, `ProjectList`).  
- Prefix reusable components with the feature name (e.g., `LogForm`, `LogList`).  

### **Files and Folders**:  
- Use `kebab-case` for file and folder names (e.g., `log-form.js`, `project-list.js`).  
- Group related files in the same folder (e.g., `components/logs/` for log-related components).

## 3. Inline Comments  
### **Purpose**: Explain complex logic, algorithms, or decisions.  
### **Guidelines**:  
- Use `//` for single-line comments.  
- Use `/** ... */` for multi-line comments.  
- Avoid over-commenting; only comment when necessary.

Example Codebase:

Frontend:

// src/components/logs/LogForm.js
import React, { useState } from 'react';
import { useStore } from '../../store';

function LogForm({ projectId }) {
  const [content, setContent] = useState('');
  const addLog = useStore(state => state.addLog);

  const handleSubmit = () => {
    if (content) {
      addLog({ projectId, content });
      setContent('');
    }
  };

  return (
    <div>
      <textarea value={content} onChange={e => setContent(e.target.value)} />
      <button onClick={handleSubmit}>Submit</button>
    </div>
  );
}

export default LogForm;

Backend:

// backend/controllers/logController.js
const Log = require('../models/Log');

exports.createLog = async (req, res) => {
  try {
    const { projectId, content } = req.body;
    const log = new Log({ projectId, content });
    await log.save();
    res.status(201).json(log);
  } catch (error) {
    res.status(500).json({ error: 'Failed to create log' });
  }
};
